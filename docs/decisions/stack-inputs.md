> **사용 방법**
> 1. 오늘은 **기술 스택을 정하지 않습니다.** 정하기 전에 필요한 **우리 팀 정보만** 정리합니다. 스택 후보 비교와 결정은 다음 차시(2주차 2일차)에 합니다.

> 3. **이름을 들어 본 기술과 직접 써서 뭘 만들어 본 기술을 구분**합니다. "JavaScript를 안다"와 "React로 서비스를 만들어 봤다"는 다릅니다. 모르는 것은 억지로 채우지 않고 `미정`으로 씁니다.
> 4. 팀원 5명이 **각자 자기 줄**을 채웁니다 (동시에 고치면 충돌하니 블록 3 합류 때 정리 담당이 한 번에 옮기거나, 한 명씩 차례로 입력).
> 5. 정리 담당이 PR로 올립니다. 이 파일은 다음 차시에 `docs/STACK.md`의 "우리 팀 상황"으로 이어집니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

## 서비스 쪽 조건

| 항목 | 우리 팀 |
| --- | --- |
| 핵심 기능 3개 (필수 스토리에서) | ① 스쿼트 목표 설정·카메라 횟수 인식·자동 제출(US-01) ② 보상 미리보기·AI 판정·중복 없는 보상 지급(US-02~04) ③ 전투 리플레이·결과 카드·자세 교정 코멘트 확인(US-05). 승인 전 취소와 애매한 건의 확인 요청·반려(US-06~08)는 첫 데모 이후 구현 |
| 화면 (웹 / 모바일, 반응형 여부) | [제안·팀 확인 필요] 모바일 우선 반응형 웹으로 운동 시작·결과 화면을 만들고 PC에서도 확인 가능하게 구성. 카메라 접근과 기기 내 자세 인식이 대상 모바일 브라우저에서 동작하는지 먼저 검증한 뒤 웹/앱 방식을 확정 |
| 시연 방식 (내 컴퓨터에서 / 외부 접속) | 3주차 첫 데모는 스쿼트 30회 제출 → 보상 미리보기 → 자동 승인 → 1회 지급 → 리플레이까지 시연. 중복 지급 요청과 LLM 장애도 확인. [제안·팀 확인 필요] 개발자 PC에서 먼저 통합 검증하고 외부 접속 가능한 테스트 환경에서 시연하며, 배포 주소·장비는 미정 |
| LLM이 맡는 일 (초안·요약·분류·설명) | 운동 기록 요약(L1), 이상치 설명(L2), 전투 서사(L3), 자세 교정 코멘트(L4) 생성. 첫 데모는 L3·L4 중심이며 자동 승인 건의 L1·L2 생성 여부는 미정. 운동 횟수·승인·보상·상태는 LLM이 결정하지 않고, 호출 실패 시 기본 문구로 진행. 주간 성장 리포트(L5)는 MVP 제외 |

근거: [MVP 범위 초안](mvp-scope.md), [필수 스토리](../requirements/backlog.md), [첫 데모 흐름](../requirements/user-flows.md), [제안서 Ⅳ-13 LLM 활용 방안](../proposal/draft.md). MVP 범위 초안도 팀 확인 전이며, 위의 제안 항목은 기술 스택 확정 전에 합의한다.

## 시간과 제약

| 항목 | 우리 팀 |
| --- | --- |
| 개발 기간 (남은 수업일 × 가능한 시간) | 팀원 5명·전체 8주 프로젝트, 주 2회 수업 기준. 3주차 첫 데모, 8주 안에 MVP 완성을 목표로 함. 남은 수업일 수와 1회당 실제 개발 가능 시간은 미정이며, 수업 외 개인별 가능 시간을 확인해 총 개발 시간을 산정해야 함 |
| 비용 제약 (무료로만 / 가능한 금액) | [제안·팀 확인 필요] 개발·시연은 무료 사용 범위를 우선 검토. 서버·DB·LLM API의 유료 사용 가능 여부와 월 예산 상한은 미정. LLM은 동일 입력 결과 재사용과 호출 한도 초과 시 기본 문구로 비용·장애에 대응 |
| 설치 권한·컴퓨터 환경 제약 | 팀원별 OS·사양, 개발 도구·DB·컨테이너 설치 권한은 미정. 카메라가 있는 시연 기기와 전신 촬영 공간이 필요하며, 대상 기기에서 자세 인식 속도·촬영 각도·카메라 권한을 사전 확인. 공통 실행 방법은 스택 결정 후 정리 |
| 외부 서비스 사용 제한 | 외부 LLM API 사용을 전제로 하되 제공사·계정·키 발급 및 수업 네트워크 접근 가능 여부는 미정. 영상은 기기 밖으로 보내지 않고, LLM에는 식별 정보를 제거한 구조화 데이터·요약 통계만 전달하며 관절 좌표 원본은 보내지 않음. 건강 앱 러닝·걸음 수 연동은 MVP 제외, LLM 장애에도 핵심 흐름은 계속 동작 |

근거: [1차 고객 미팅](../interview/client-meeting-1.md), [MVP 범위 초안](mvp-scope.md), [제안서](../proposal/draft.md), [일일 기록 양식의 수업 주기](../../logs/daily/daily-log-template.md). 예산·장비·수업별 가능 시간은 팀 확인 후 갱신한다.
