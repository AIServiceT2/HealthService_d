## 포함 (8주 안에 반드시 동작 — 필수 스토리 전부, 취소·반려 스토리 포함)
| 스토리 | 기능 (F-__) | 왜 필수인가 |
| --- | --- | --- |
| US-01 운동하면 렙을 세어 자동 제출 (스쿼트) | F-02, F-10, F-11(즉시 피드백) | 서비스의 출발점. 인증샷 대신 카메라가 세는 것이 핵심 가치이고, 고객이 자세 인식 모델을 가장 중요하다고 함 (피드백 6·15) |
| US-02 보상·타격 수 미리보기 | F-03 | `SUBMITTED → PREPARED` 전이. 보상 스냅샷을 고정해야 이후 지급·회수가 같은 값을 쓸 수 있음 |
| US-03 AI 확신도 기준 이상이면 바로 승인 | F-04 | 고객이 "승인을 기다리면 리텐션이 떨어진다"고 함 (피드백 7, 질의응답 2) |
| US-04 보상을 한 번만 반영 | F-05 | 같은 요청이 반복돼도 한 번만 반영하는 설계를 잘 보여 달라는 고객 요청 (피드백 17) |
| US-05 리플레이·결과 카드·교정 코멘트 보기 | F-06, F-13 | 운동이 전투가 되는 장면이 서비스의 차별점. 자세 교정은 고객이 LLM 가치로 요청함 (피드백 3·12) |
| US-06 승인 전 제출 취소 | F-02 | 과제 필수 조건인 취소 경로. 상한 예약 해제와 취소·승인 동시 처리를 검증해야 함 |
| US-07 애매한 건을 지인·길드장에게 확인 요청 | F-04 | 반려(US-08)가 일어나려면 `PENDING_REVIEW`가 있어야 함. 고객이 확신도 90% 미만은 사람이 확인하는 구조를 요청함 (질의응답 2). backlog에는 '선택'으로 되어 있어 '필수'로 고쳐야 함 |
| US-08 확인자가 사유와 함께 반려 | F-04 | 과제 필수 조건인 반려 경로. 성공 지표 "반려건 사유 기록 100%"의 대상 (제안서 Ⅴ). backlog에는 '선택'으로 되어 있어 '필수'로 고쳐야 함 |
| (스토리 없음: backlog에 추가 필요) 신고·회수 | F-07 | 제안서 Ⅰ-3에서 최종 MVP에 회수 경로를 넣기로 함. 다만 이미 쓴 아이템의 롤백 범위가 정해지지 않음 ('여전히 가정' 5행) |
| (US-01~05의 전제) 회원·캐릭터·길드 | F-01 | 로그인 계정, 길드장 찾기(US-07), 보스 피해 반영(US-04)에 필요함. 아바타 꾸미기는 최소한으로 함 |

## 제외 (이번에 만들지 않음)
| 제외 항목 | 왜 뺐는가 | 나중에 넣으면 영향 범위 |
| --- | --- | --- |
| 스쿼트 외 운동(푸시업·플랭크 등)과 약점 배율 | 운동마다 판정 기준·촬영 각도 테스트가 필요하고, 고객이 답한 일일 상한이 스쿼트·러닝뿐이라 경계값이 정해지지 않음. 스쿼트 1종의 인식 정확도를 먼저 확보함 (피드백 6). 일정이 남으면 M2에서 추가 | 운동별 판정 기준, 카탈로그 스킬, 일일 상한 값, 약점 배율 계산(F-03), US-01·US-02 테스트 |
| 휴식 경고·경고 3회 초과 시 공격 실패 (F-11 일부) | 기준 시간이 정해지지 않았고, 공격 실패 때 운동 기록을 지우면 "운동은 헛되지 않는다" 원칙과 충돌함 ('여전히 가정' 6행) | 카메라 세션 로직, 제출건의 인정량·보상 계산, 리플레이(공격 실패 표시) |
| 오각형 성장 리포트 (F-12, LLM L5) | 다섯 번째 축이 정해지지 않음 ('여전히 가정' 4행). LLM 가치에 대한 고객 요청(피드백 12)은 필수 기능인 자세 교정 코멘트(F-13)로 먼저 대응함 | 능력치 모델(축 추가), 리포트 화면, LLM L5 프롬프트·대체 문구 |
| 걸음 수 체력 회복 (F-09) | 건강 앱 연동이 필요한데, 같은 연동인 러닝이 후순위로 정해짐 (질의응답 6). 체력이 없어도 핵심 흐름(제출→지급→리플레이)은 돌아감 | 건강 앱 권한·동의, 캐릭터 체력, 던전 입장 조건 |
| 건강 앱 러닝 연동과 재제출 (`REJECTED → SUBMITTED`) | 고객이 러닝은 기존 앱이 많아 우선순위가 낮다고 함 (질의응답 6). 재제출은 연동 세션에만 해당하므로 함께 빠짐 | F-02 제출 경로(48시간 기한·수동 입력 검사), 상태 전이 `REJECTED → SUBMITTED`, 러닝 일일 상한(10km) 테스트 |
| 음성 인식 (F-14) | 부가 기능. 시끄러운 곳에서 불안정할 수 있고, 목표 개수·세트를 먼저 정하는 방식으로 운동 중 조작이 필요 없음 (피드백 18) | 카메라 세션 화면, 권한(마이크) |
| 숙련도 이펙트·보상 상자 연출 | 고객이 게임 요소는 가볍게 하라고 함 (피드백 1·2). 수치와 리플레이만으로 결과가 전달됨 | 리플레이·결과 카드 화면 |
| 확장 운동 4종, 스킬 연계 콤보, 여러 지역·막타 보너스 | 5명·8주 안에서 게임 요소의 비중을 낮추고 자세 인식에 시간을 쓰기 위해 (피드백 1) | 카탈로그, 보상 계산(F-03), 레이드 규칙 |
| 거래·강화·제작, 직업, 길드 채팅, 자유 대화형 NPC | 운동 지속과 직접 관련이 없고 구현 범위가 큼 (피드백 1·2) | 아이템 상태(회수 규칙 R8과 충돌 가능), 별도 화면·API |
| GPS 경로·심박 수집, 웨어러블 직접 연동 | 동의 범위를 넘는 건강·위치 정보를 모으지 않기 위해 (03 R17) | 개인정보 처리방침, 동의 화면, 데이터 저장 구조 |
| 검토용 3D 모델링 | 작업량이 큼. 관절 선 또는 실루엣으로 얼굴 없이 확인할 수 있음 (피드백 19) | 확인자 화면(US-07) |
| 고도화된 도용 탐지 | 시작 시 무작위 동작 확인과 사람 확인·신고로 1차 대응. 탐지 기준을 세울 데이터가 아직 없음 | AI 판정(F-04), 신고·회수(F-07) |

## 첫 데모(3주차)에서 보여줄 것
(user-flows.md의 흐름과 같음)

스쿼트 30회 정상 경로 하나를 처음부터 끝까지 보여 준다: `SUBMITTED` → `PREPARED` → `APPROVED` → `REWARDED`

1. 스쿼트를 고르고 튜토리얼(판정 기준·촬영 각도)을 본 뒤 목표 30회 × 1세트와 공략 대상을 정함 (F-10)
2. 카메라 앞에서 스쿼트 30회. 기기 안의 모델이 한 개씩 세며 인정 여부를 바로 보여 줌. 영상은 기기 밖으로 나가지 않음 (F-11 즉시 피드백)
3. 세션이 끝나면 얼굴을 뺀 관절 좌표만 보내 자동 제출, 시간대 중복·일일 상한 검사 (`SUBMITTED`, F-02)
4. 보상·타격 수 계산과 스냅샷 고정, LLM이 서사(L3)·교정 코멘트(L4)를 만듦 (`PREPARED`, F-03)
5. 보상 미리보기 "충격파 스톰프 ×30" 확인
6. 확신도가 기준(90%) 이상이라 바로 승인 (`APPROVED`, F-04)
7. 보상을 정확히 한 번 반영, 24시간 보호 기간 시작 (`REWARDED`, F-05)
8. 리플레이(30 COMBO)·결과 카드·서사·교정 코멘트 확인 (F-06, F-13)

데모에서 함께 확인할 것: 지급 요청을 두 번 보내도 한 번만 반영됨, LLM을 꺼도 기본 문구로 `PREPARED`까지 감.
첫 데모에서 빼는 것: 취소·사람 확인·반려·회수 경로(US-06~08, F-07)는 첫 데모 뒤에 만듦.

## 고객이 요청했으나 제외한 것

| 요청 | 제외 이유 | 다시 논의할 시점 |
| --- | --- | --- |
| 애매한 건을 담당자(운영자)가 승인 (피드백 8) | 운영자 인원을 아직 모르고(질의응답 5), 고객도 애매한 건은 길드원이 확인하는 구조를 말함. 운영자에게는 AI 판정 문의만 보냄 | 다음 미팅 (운영자 인원 확인 후) |
| 애매한 건을 다른 길드원에게 넘기기 (피드백 9) | 다른 길드원은 확인할 동기가 없음(피드백 10). 사용자가 고른 지인·길드장에게 보내도록 대상만 바꿈 | 다음 미팅 (지인·길드장 방식이 괜찮은지 확인) |
| 움직임을 감지해 터치처럼 쓰기 (피드백 18) | 목표 개수·세트를 먼저 정하고 AI가 자동으로 세서 운동 중 조작 자체가 필요 없음 | 첫 데모 후 사용 테스트에서 운동 중 조작이 필요하다고 나오면 |
| 음성 인식으로 카메라 켜고 끄기 (피드백 18) | 부가 기능으로 둠. 시끄러운 곳에서 불안정할 수 있음 | M2 일정 여유가 있을 때 |
| 오각형 성장 리포트 (피드백 12) | 다섯 번째 축이 정해지지 않음. LLM 가치는 자세 교정 코멘트(F-13)로 먼저 보여 줌 | 다음 팀 회의(축 결정) 후 다음 미팅 |
| 검토용 3D 모델링 (피드백 19 논의 중 나온 대안) | 작업량이 큼. 관절 선·실루엣으로 대신함 | 보류 (다시 논의하지 않음) |
| 초보 운동인을 위한 주간 플랜 (피드백 4) | 아직 '추가 확인' 상태. 범위가 커질 수 있어 고객이 원하는지부터 확인함 | 다음 미팅 |

## 제안서(v2)와 다른 점

| 제안서 절 | 제안서(v2)에 적힌 것 | 이 문서(MVP)에서 달라진 것 |
| --- | --- | --- |
| 제안 요약 '핵심 기능 3가지' ① | 운동 제출에 "취소·재제출 포함" | 재제출은 러닝 연동과 함께 MVP에서 빠짐. 취소만 포함 |
| Ⅳ-9 서비스 개요 '한 줄 정의' | "걸은 만큼 회복한다" | 걸음 수 체력 회복(F-09)은 MVP에서 제외 |
| Ⅳ-10 목표 흐름 2단계 | 쉬는 시간이 길면 경고, 3회 초과 시 공격 실패 | 휴식 경고는 MVP에서 제외 |
| Ⅳ-10 목표 흐름 6단계 | 오각형 성장 리포트를 보고, 걸은 만큼 체력 회복 | 오각형 리포트·걸음 수 체력 회복 모두 제외 |
| Ⅳ-11 F-04 우선순위 | 필수 (자동 승인 + 확인 요청·반려 전체) | 같음. 다만 backlog에서는 확인 요청(US-07)·반려(US-08)가 '선택'이라 backlog를 '필수'로 고쳐야 함 |
| Ⅳ-11 F-07 신고·회수 | 선택 | 포함 (Ⅰ-3 "최종 MVP에는 취소·반려·회수 경로를 포함"에 따름). 같은 제안서 안에서 Ⅰ-3과 Ⅳ-11이 서로 다름 |
| Ⅳ-11 F-11 즉시 피드백·휴식 경고 | 필수 (휴식 경고 포함) | 즉시 피드백만 필수, 휴식 경고는 제외 |
| Ⅳ-11 F-03 LLM 생성 | `PREPARED`에서 L1·L2·L3·L4를 모두 생성 | 자동 승인 건에도 L1·L2를 만들지 미정 (user-flows 미확정 2행) |
