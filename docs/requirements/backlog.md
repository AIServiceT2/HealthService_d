## US-01 운동하면 렙을 세어 자동 제출

**플레이어로서, 고른 운동을 카메라 앞에서 하면 기기가 렙을 세어 자동으로 제출되기를 원한다. 횟수를 직접 세거나 인증샷을 올리지 않고 맨몸 운동을 기록으로 남기기 위해.**

- 우선순위: 필수
- 관련 기능: F-02, F-10, F-11(즉시 피드백만)
- 경로: 정상
- 관련 상태 전이: (없음) → `SUBMITTED`
- LLM 관여: 아니오
- 근거: user-flows 1~3단계, 03 3-2 첫 전이, R1·R2·R3·R11·R12
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 스쿼트를 고르고 세션을 끝내면, 기기가 센 인정 렙 수(예: 30)를 인정량으로 가진 `SUBMITTED` 제출건이 1개 생기고, 운동 종류는 스쿼트 하나만 기록된다
- [ ] (정상) 제출 후 그날(KST) 스쿼트 상한 예약량이 인정 렙 수만큼 늘어난다 (0회 → 30회)
- [ ] (정상) 서버로 전송된 데이터에는 영상 파일과 얼굴 랜드마크 좌표가 없고, 얼굴을 뺀 관절 좌표와 렙 타임스탬프만 있다
- [ ] (실패·거절) 그날 스쿼트 인정량이 이미 200회인 상태에서 30회를 하면 제출건은 기록되지만 보상 대상 인정량은 0이다
- [ ] (실패·거절) 같은 사용자에게 같은 시간대의 활성 스쿼트 제출건이 있으면 새 제출건이 만들어지지 않고 거부 응답이 온다
- [ ] (실패·거절) 가동범위 기준에 못 미친 렙은 화면에 미인정으로 표시되고 인정량에 들어가지 않는다. 사용자가 인정 렙 수를 늘리는 요청은 거부된다
- [ ] (권한) 제출건은 로그인한 본인 계정으로만 만들어지고, 다른 사용자의 계정으로 제출을 요청하면 거부된다

### 미확정
- 세션 시작 시 무작위 동작 확인에 실패하면 세션을 다시 시작하게 할지, 제출은 하되 자동 승인 대상에서 뺄지
- 푸시업·플랭크 등 나머지 운동의 일일 상한 (고객은 스쿼트 200회·러닝 10km만 답함)
- 인정이 잘 되는 촬영 각도 (3주차 첫 데모 전 카메라 각도 테스트 후)

## US-02 보상·타격 수 미리보기

**플레이어로서, 제출한 운동의 보상과 타격 수를 미리 보고 싶다. 내 운동이 어떤 공격이 될지 바로 알기 위해.**

- 우선순위: 필수
- 관련 기능: F-03
- 경로: 정상
- 관련 상태 전이: `SUBMITTED` → `PREPARED`
- LLM 관여: 예 (L3·L4 생성)
- 근거: user-flows 4~5단계, 03 3-2, R5·R9
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) `SUBMITTED` 건의 계산이 끝나면 상태가 `PREPARED`가 되고, 인정 렙 30회 스쿼트의 타격 수는 30으로 저장된다
- [ ] (정상) 스냅샷에 카탈로그 버전·확정 능력치·약점 배율·AI 판정 확신도가 저장되고, 이후 운영자가 카탈로그를 바꿔도 이 제출건의 보상 수치는 바뀌지 않는다
- [ ] (실패·거절) 보상 계산이 실패하면 상태는 `SUBMITTED`에 남고, 재시도해서 계산이 성공했을 때만 `PREPARED`가 된다
- [ ] (실패·거절) LLM 호출이 실패해도 상태는 `PREPARED`가 되고, `ai_story`·`ai_form_tip`에는 미리 정한 기본 문구가 저장된다
- [ ] (권한) 보상 미리보기는 제출한 본인에게만 보이고, 다른 사용자가 같은 제출건의 미리보기를 요청하면 거부된다
- [ ] (LLM) LLM이 만든 `ai_story`·`ai_form_tip`은 제출건 상태와 보상 수치(경험치·피해량·타격 수)를 바꾸지 않는다. 같은 제출건에서 LLM 출력이 달라져도 보상 수치는 같다
- [ ] (LLM) L3 요청에는 스킬명·운동 종류·적 이름·약점 적중 여부만, L4 요청에는 판정 기준·관절 각도 요약 통계·미인정 사유만 담기고, 수치·메모·관절 좌표 원본·얼굴 정보·닉네임·길드명은 담기지 않는다 (제안서 Ⅳ-13)

### 미확정
- AI 자동 승인 건에도 L1·L2를 만들지 (보는 사람이 없어 호출 비용만 듦)
- LLM 실패 시 보여 줄 기본 문구의 내용

## US-03 AI 확신도 기준 이상이면 바로 승인

**플레이어로서, AI 판정 확신도가 기준 이상이면 누구의 승인도 기다리지 않고 바로 승인받고 싶다. 운동 직후 성취감이 끊기지 않게 하기 위해.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 정상
- 관련 상태 전이: `PREPARED` → `APPROVED`
- LLM 관여: 아니오
- 근거: user-flows 6단계, 제안서 Ⅳ-12, 03 3-2
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 확신도가 기준(90%) 이상이고 무작위 동작 확인을 통과한 `PREPARED` 건은 사람 확인 없이 `APPROVED`가 된다
- [ ] (정상) 승인된 제출건에 승인 경로(AI 자동 승인)와 확신도 값이 기록된다
- [ ] (실패·거절) 확신도가 기준 미만인 건은 `APPROVED`가 되지 않고 `PREPARED`에 머물며, 신청자 화면에 확인 요청 보내기 버튼이 나타난다
- [ ] (실패·거절) 무작위 동작 확인을 통과하지 못한 세션의 제출건은 확신도와 관계없이 자동 승인되지 않는다
- [ ] (실패·거절) `PREPARED`를 거치지 않고 `SUBMITTED`에서 바로 `APPROVED`로 바꾸는 요청은 거부된다
- [ ] (권한) 플레이어와 확인자는 확신도 값이나 승인 상태를 직접 바꿀 수 없고, 그런 요청은 거부된다

### 미확정
- 확신도 기준 90% 확정 (3주차 첫 데모 전 자세 인식 모델 테스트 후)

## US-04 보상을 한 번만 반영

**플레이어로서, 승인된 운동의 보상이 한 번만 반영되기를 원한다. 같은 요청이 반복돼도 보상이 두 번 들어오거나 빠지지 않게 하기 위해.**

- 우선순위: 필수
- 관련 기능: F-05
- 경로: 정상
- 관련 상태 전이: `APPROVED` → `REWARDED`
- LLM 관여: 아니오
- 근거: user-flows 7단계, 03 3-2, R7
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) `APPROVED` 건이 지급되면 상태가 `REWARDED`가 되고, 경험치·아이템·능력치 경험치·보스(또는 던전) 피해가 스냅샷에 저장된 값만큼 한 번 늘어난다
- [ ] (정상) 지급 직후 얻은 아이템은 `LOCKED`, 능력치 경험치는 '확정 대기'로 표시되고, 지급 후 24시간이 지나기 전에는 위력·방어 계산에 들어가지 않는다
- [ ] (실패·거절) 같은 지급 요청이 두 번 오면 두 번째 요청은 첫 번째 결과를 그대로 돌려주고, 경험치·아이템·피해량은 다시 늘지 않는다
- [ ] (실패·거절) 지급 중 오류가 나면 상태는 `APPROVED`에 남고 보상은 하나도 반영되지 않으며, 재시도가 성공했을 때만 `REWARDED`가 된다
- [ ] (실패·거절) `APPROVED`가 아닌 건(`PREPARED`, `CANCELED` 등)에 대한 지급 요청은 거부된다
- [ ] (권한) 지급은 시스템만 실행하고, 플레이어가 지급을 직접 요청하면 거부된다. 다른 사용자는 남의 지급 내역을 볼 수 없다

### 미확정
- 데모에서 공략 대상을 던전 적으로 할지 주간 보스로 할지 (반영되는 값이 던전 공략 / 보스 체력으로 달라짐)

## US-05 리플레이·결과 카드·교정 코멘트 보기

**플레이어로서, 내가 한 횟수만큼 캐릭터가 공격하는 리플레이와 결과 카드, 다음에 고칠 점을 보고 싶다. 운동 결과가 성장과 이야기로 이어지는 걸 느끼기 위해.**

- 우선순위: 필수
- 관련 기능: F-06, F-13
- 경로: 정상
- 관련 상태 전이: `REWARDED` (상태 변경 없이 결과 표시)
- LLM 관여: 예 (L3·L4 표시)
- 근거: user-flows 8단계, R9·R10
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) `REWARDED` 건의 리플레이 콤보 수는 결과 카드의 타격 수와 같다 (인정 렙 30회 → 30 COMBO)
- [ ] (정상) 리플레이는 30초를 넘지 않고, 스킵을 누르면 결과 카드로 넘어간다
- [ ] (실패·거절) `REWARDED`가 아닌 건(`PREPARED`, `CANCELED` 등)은 리플레이를 열 수 없다
- [ ] (실패·거절) 일일 상한 초과로 타격 수가 0이면 리플레이 없이 "일일 상한 초과" 카드가 나온다
- [ ] (실패·거절) 서사 후보에 숫자·다른 스킬명·아이템명이 있으면 저장하지 않고 다시 만들며, 2번 실패하면 기본 문구가 나온다
- [ ] (권한) 리플레이·결과 카드·교정 코멘트는 본인에게만 보이고, 다른 사용자가 요청하면 거부된다
- [ ] (LLM) 서사·코멘트를 표시하거나 다시 만드는 일은 제출건 상태와 결과 카드의 수치를 바꾸지 않는다
- [ ] (LLM) 서사를 다시 만드는 요청에도 수치·메모·관절 좌표 원본·닉네임은 담기지 않는다 (제안서 Ⅳ-13)

### 미확정
- 같은 길드원에게 리플레이를 공개할지
- 교정 코멘트에서 거를 "진단·처방처럼 들리는 표현"의 기준

## US-06 승인 전 제출 취소

**플레이어로서, 승인되기 전에는 제출을 취소하고 싶다. 잘못 제출한 기록이 보상과 일일 상한에 반영되지 않게 하기 위해.**

- 우선순위: 필수
- 관련 기능: F-02
- 경로: 취소·반려
- 관련 상태 전이: `SUBMITTED` / `PREPARED` / `PENDING_REVIEW` → `CANCELED`
- LLM 관여: 아니오
- 근거: user-flows 포함하지 않은 경로(취소), 03 3-2
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 신청자가 `SUBMITTED`·`PREPARED`·`PENDING_REVIEW` 건을 취소하면 상태가 `CANCELED`가 된다
- [ ] (정상) 취소하면 그 건이 예약한 일일 상한 인정량이 해제되어, 그날 스쿼트 상한 예약량이 취소 전보다 그만큼 줄어든다
- [ ] (실패·거절) `APPROVED`·`REWARDED` 건의 취소 요청은 거부되고 상태가 바뀌지 않는다
- [ ] (실패·거절) 취소와 승인이 동시에 오면 먼저 처리된 하나만 반영되고 나중 요청은 거부된다. 취소가 먼저 처리되면 지급은 0건이다
- [ ] (실패·거절) `CANCELED` 건은 다른 상태로 바뀌지 않는다
- [ ] (권한) 신청자 본인만 취소할 수 있고, 확인자·길드장·다른 사용자의 취소 요청은 거부된다
- [ ] (취소·반려 스토리) 신청자가 승인 전(`SUBMITTED` / `PREPARED` / `PENDING_REVIEW`)에 취소하면 `CANCELED`로 가고, 그 건에는 이후 보상 지급과 리플레이가 생기지 않는다

### 미확정
- 승인 전 취소가 가능한 시점. 확신도가 기준 이상이면 `PREPARED → APPROVED`가 바로 일어나서, 정상 경로에서는 취소 버튼을 누를 틈이 거의 없음

## US-07 애매한 건을 지인·길드장에게 확인 요청

**플레이어로서, AI가 애매하다고 판단한 기록은 보낼 내용을 미리 보고 지인이나 길드장에게 확인을 요청하고 싶다. 얼굴을 보여 주지 않고 사람의 확인을 받기 위해.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 사람 확인 (첫 데모 흐름 밖)
- 관련 상태 전이: `PREPARED` → `PENDING_REVIEW` → `APPROVED`
- LLM 관여: 예 (L1·L2 표시)
- 근거: user-flows 포함하지 않은 경로(사람 확인), 제안서 Ⅳ-12, 03 3-2
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 확신도 기준 미만인 `PREPARED` 건에서 신청자가 확인자(지인 또는 길드장) 1명을 골라 보내면 상태가 `PENDING_REVIEW`가 된다
- [ ] (정상) 보내기 전에 보낼 내용(관절 선 또는 실루엣, 운동 종류, 제출 간격 통계)의 미리보기가 나오고, 신청자가 확인을 누른 뒤에만 전송된다
- [ ] (실패·거절) 이미 `APPROVED`된 건에는 보내기 버튼이 없고, 보내기 요청은 거부된다
- [ ] (실패·거절) 신청자 본인을 확인자로 고르면 거부된다
- [ ] (권한) 확인자 화면에는 얼굴·나이·길드명이 나오지 않고, 요청받지 않은 사용자는 그 건을 볼 수 없다
- [ ] (LLM) 확인 화면의 `ai_summary`·`ai_flags`는 표시만 되고, 확인자가 승인이나 반려를 누르기 전까지 상태는 `PENDING_REVIEW`에서 바뀌지 않는다
- [ ] (LLM) L1·L2 요청에는 닉네임·길드명, 메모 속 이름·연락처·장소, 관절 좌표 원본, 건강 앱 원본 데이터가 담기지 않고, 관절 좌표는 통계로만 보낸다 (제안서 Ⅳ-13)

### 미확정
- 신청자가 아무에게도 보내지 않거나 확인자가 응답하지 않을 때의 처리
- "지인"을 어떻게 정할지 (친구 목록 등)
- 봐주기를 막기 위한 보상 제한·운영자 표본 재검토 여부

## US-08 확인자가 사유와 함께 반려

**확인자(지인·길드장)로서, 실제로 한 운동이 아니라고 보이면 사유 코드와 설명을 남기고 반려하고 싶다. 부정한 기록이 보상을 받지 못하게 하기 위해.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 취소·반려
- 관련 상태 전이: `PENDING_REVIEW` → `REJECTED` → `CLOSED`
- LLM 관여: 아니오
- 근거: user-flows 포함하지 않은 경로(반려), 03 3-2, R6
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 확인자가 사유 코드(`기록이상` / `본인확인실패` / `도용의심`)와 설명을 입력해 반려하면, 카메라 세션 건은 `REJECTED`를 거쳐 `CLOSED`가 된다
- [ ] (정상) 반려되면 그 건이 예약한 일일 상한 인정량이 해제되고 보상은 지급되지 않는다
- [ ] (실패·거절) 사유 코드나 설명 없이 반려를 요청하면 거부되고 상태는 `PENDING_REVIEW`에 남는다
- [ ] (실패·거절) AI 판정이나 `ai_flags`만으로는 반려되지 않고, 확인자의 반려 요청이 있어야 `REJECTED`가 된다
- [ ] (실패·거절) `CLOSED` 건은 재제출되거나 다른 상태로 바뀌지 않는다
- [ ] (권한) 그 건을 요청받은 확인자만 반려할 수 있고, 신청자 본인과 요청받지 않은 사용자의 반려 요청은 거부된다
- [ ] (취소·반려 스토리) 확인자가 `PENDING_REVIEW` 건을 사유와 함께 반려하면 `REJECTED` → `CLOSED`로 가고, 신청자는 새 세션으로 다시 운동해야 한다

### 미확정
- 운영자의 도용 확정 절차
- 반려 사유와 설명을 신청자에게 어디까지 보여 줄지
