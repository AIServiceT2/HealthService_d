## 연결된 상태 전이
03-rules-states-llm.md의 핵심 대상: 운동 제출건 (WorkoutSubmission)
지나가는 상태: `SUBMITTED` 제출됨 → `PREPARED` 계산 완료 → `APPROVED` 승인 (AI 판정) → `REWARDED` 지급 완료 (4개)

- 1차 미팅 결과(client-meeting-1 피드백 7·8, 질의응답 2)를 반영한 제안서 v2 Ⅳ-12의 정상 경로를 따른다. AI 판정 확신도가 기준(90%) 이상이면 사람 확인 없이 `PREPARED → APPROVED`로 간다.
- 03 3-2 표도 이 흐름(AI 자동 승인 `PREPARED → APPROVED`, 기준 미만은 지인·길드장 확인)에 맞게 고쳤다 (2026-10-27).

## 이 흐름에 포함하지 않은 경로

- 취소·반려는 backlog.md의 필수 스토리 US-06(취소)·US-08(반려)에서 다룬다
  - 취소 (US-06): `SUBMITTED` / `PREPARED` / `PENDING_REVIEW` → `CANCELED` (승인 전 신청자 취소, 상한 예약 해제, 취소와 승인이 동시에 오면 먼저 성공한 한 건만 인정)
  - 반려 (US-08): `PENDING_REVIEW` → `REJECTED` → `CLOSED` (확인자가 사유 코드 `기록이상` / `본인확인실패` / `도용의심`과 설명을 남기고 반려. 카메라 세션은 재제출할 수 없어 `CLOSED`, 상한 예약 해제)
- 애매한 건의 사람 확인 (US-07): 확신도가 기준 미만이면 `PREPARED` → `PENDING_REVIEW` (신청자가 보낼 내용을 미리 보고 지인·길드장에게 보냄) → `APPROVED` / `REJECTED`. MVP에는 포함하지만 첫 데모에서는 제외
- 재제출 `REJECTED` → `SUBMITTED`: 연동 러닝 세션만 해당하고 러닝 연동이 후순위라 MVP에서는 없음 (제안서 Ⅳ-11 F-02)
- 신고·회수 `REWARDED` → `REVOKED`: F-07 선택 기능, MVP에서 제외 (mvp-scope.md)
- 접수 단계의 실패: 같은 시간대 활성 스쿼트 건이 있으면 접수 거부(R3), 일일 상한을 넘은 인정량은 기록만 남기고 보상·타격 0, 리플레이 없이 "일일 상한 초과" 카드(R1·R9)
- 시스템 실패: 계산 실패 시 `SUBMITTED` 유지 후 재시도, 지급 실패 시 `APPROVED` 유지 후 지급만 재시도 (03 3-2)
- 첫 데모에서 뺀 기능: 휴식 경고·경고 3회 공격 실패(F-11 일부), 오각형 성장 리포트(F-12), 나머지 운동·약점 배율, 걸음 수 체력 회복(F-09), 러닝 연동, 음성 인식(F-14), 숙련도 이펙트·보상 상자 연출 (제안서 Ⅰ-3 '이번에 하지 않는 것')
