| 항목 | 적용 기준 | 근거·구분 |
| --- | --- | --- |
| 테마 | 검정 `#000000` 바탕, 형광 라임 `#B9FD50` 강조 | PRD 9절 · 기존 기준 |
| 강조 위치 | 주요 버튼, 선택 상태, 운동 부위 강조 | PRD 9절 · 기존 기준 |

| 내비게이션 | 홈에서 운동 시작·본인 기록·받은 확인 요청으로 진입. 상세는 뒤로가기로 복귀. 탭 구성은 미정 | PRD 5절이 비어 있어 제안으로 둠 |

### 실루엣과 선택 UI 적용 [제안]

- 운동 준비 화면에서 스쿼트의 운동 부위를 실루엣에 라임으로 표시하고 부위 이름을 함께 제공한다. MVP에서 선택 가능한 운동은 스쿼트 하나로 제한한다. 부위별 정확한 표시 범위와 이미지 자산은 팀 검토 후 정한다. (근거: PRD 9·10절)
- 결과 화면의 실루엣은 해당 운동 부위를 설명하는 보조 시각 요소로 사용한다. 회복률·근육 피로도·성장 백분율을 임의로 계산하거나 표시하지 않는다. 참고 서비스의 기능이 MVP 요구사항을 뜻하지는 않는다. (근거: PRD 9절, MVP 범위 제외)
- 선택된 알약 버튼은 `primary` 배경과 `onPrimary` 글자, 선택되지 않은 버튼은 `surface` 배경과 `text` 글자·테두리를 사용한다. 선택 표시와 접근성 선택 상태를 함께 제공한다.
- 확인자에게 보여 주는 관절 선·실루엣은 운동 부위 안내용 그림과 용도가 다르다. 실제 요청의 검토 자료를 표시하며 얼굴·나이·길드명을 제외한다. (출처: 백로그 US-07, 고객 미팅 피드백 19)

## 2. 디자인 토큰

주 색상과 배경색은 PRD의 값을 유지한다. 나머지 값은 **[제안·팀 확인 필요]**이며 기존에 확정된 값처럼 취급하지 않는다. 토큰 이름은 구현을 위한 제안이고, NativeWind 설정 파일 경로는 앱 구조 확정 후 정한다.

### 색상

| 이름 | 값 | 사용 위치 | 근거·구분 |
| --- | --- | --- | --- |

### 간격·글자·형태

수치가 명시된 기존 문서는 없어 아래 값은 모두 **[제안]**이다. 간격·크기는 React Native 논리 단위를 사용하고, 글자는 시스템 크기 설정을 반영한다.

| 이름 | 값 | 사용 위치 |
| --- | --- | --- |
| `space` | `4` | 간격 기본 단위 |
| `space2` / `space3` | `8` / `12` | 라벨·아이콘·카드 요소 사이 |
| `space4` | `16` | 화면 좌우·카드 안쪽 여백 |
| `space6` / `space8` | `24` / `32` | 섹션·큰 블록 사이 |
| `fontCaption` | `14`, 행간 `20` | 보조 설명 |
| `fontBody` | `16`, 행간 `24` | 본문·입력·버튼 |
| `fontTitle` | `24`, 행간 `32`, 굵게 | 화면 제목 |
| `fontCounter` | `48`, 행간 `56`, 굵게 | 운동 중 인정 횟수 |

기본 글꼴은 OS 기본 글꼴 사용을 제안한다. 버튼 높이는 최소값으로 두고 글자가 커지면 늘린다. 비활성 이유는 인접 문구로 표시하며 투명도만 낮춰 설명을 읽기 어렵게 만들지 않는다.

- 카메라 영상은 저장·전송하지 않는다. 전송 대상은 얼굴 랜드마크를 제외한 관절 좌표와 렙 타임스탬프다. 이를 카메라 준비 화면에 안내한다. (출처: PRD 2절, 백로그 US-01)
- 목표 입력과 측정된 인정 횟수 표시를 분리하고 횟수 늘리기는 제공하지 않는다. 도메인 R12는 측정 횟수 줄이기를 허용한다. 줄이기 조작의 위치·시점과 서버 반영 계약은 백로그에 없어 추가 확인한다. 확인자 화면에는 얼굴·나이·길드명을 표시하지 않는다. (출처: 백로그 US-01·07, 도메인 규칙 R12)
- 신고·회수, 러닝 재제출, 성장 리포트, 음성 인식, 길드 채팅 등 제외 기능의 화면·버튼은 만들지 않는다. (출처: MVP 범위 제외)

## 4. 처리 상태와 행동

상태의 기준은 서버 응답이다. 버튼을 눌렀거나 애니메이션이 끝났다는 이유만으로 승인·지급 완료로 표시하지 않는다. 아래 표시 문구는 [제안]이며, 전이와 행동 조건은 백로그 US-02~08을 따른다.

| 서버 상태 | 화면 문구 [제안] | 표시·행동 규칙 |
| --- | --- | --- |
| `SUBMITTED` | 운동 기록을 접수했어요. 보상을 계산 중이에요 | 계산 실패 시 상태 유지. 본인에게 제출 취소 제공 |
| `PREPARED` | 보상 미리보기 · 아직 지급 전이에요 | 고정된 예상 보상 표시. 자동 승인 조건을 충족하면 시스템이 진행. 확신도 기준 미만이면 확인 요청 제공. 본인 취소 가능 |
| `PENDING_REVIEW` | 확인자의 검토를 기다리고 있어요 | 요청받은 확인자만 승인·반려 가능. 신청자는 취소 가능 |
| `APPROVED` | 승인됐어요. 보상을 반영 중이에요 | 취소·확인 요청 숨김. 지급은 시스템만 실행하며 사용자용 지급 버튼은 없음 |
| `REWARDED` | 보상이 반영됐어요 | 결과·리플레이 진입. 아이템 `LOCKED`와 능력치 경험치 ‘확정 대기’를 별도 표시 |
| `CANCELED` | 제출이 취소됐어요 | 보상·리플레이 없음. 새 운동 시작으로 안내 |
| `REJECTED` | 반려됐어요. 기록을 종료 중이에요 | 보상·리플레이 없음. 카메라 세션은 `CLOSED`로 이어짐 |
| `CLOSED` | 종료된 기록이에요 | 기존 건 재제출 버튼 없음. 다시 운동하려면 새 세션 시작 |

- 자동 승인은 확신도 90% 이상뿐 아니라 판정 기준·무작위 동작 확인 조건도 충족해야 한다. 90%는 현재 요구사항의 기준이며 최종 적용은 모델 테스트 후 확인할 항목이다(PRD 미정). 확신도가 낮은 건은 보내기 성공 전까지 `PREPARED`이며, 미리보기만 열었다고 `PENDING_REVIEW`가 되지 않는다. (출처: PRD 2·7절, 백로그 US-03·07)
- 취소와 승인이 경합하면 서버에서 먼저 성공한 결과를 반영한다. 취소 실패 시 최신 상태를 다시 읽고 이유를 안내한다. (출처: 백로그 US-06)
- 지급 후 24시간 동안 아이템 잠금과 능력치 확정 대기를 구분한다. 확정 대기 능력치를 현재 전투 능력치에 더해 보여 주지 않는다. (출처: 백로그 US-04)
- 일일 상한 초과로 타격 수가 0인 건은 리플레이 대신 ‘일일 상한 초과’ 카드와 기록을 보여 준다. 네트워크 오류나 반려로 표현하지 않는다. (출처: 백로그 US-01·05)

## 5. 빈 화면·오류·로딩

이 절의 문구·배치는 **[제안]**이다. 실패 후 상태 유지, 중복 지급 방지, 접근 권한은 백로그 인수 조건을 따른다. 로딩·오류·조회 결과 0건을 구분하고, 실패한 조회를 빈 목록으로 표시하지 않는다.

### 공통 원칙

- 최초 조회는 제목·자리 표시와 ‘불러오는 중’을 표시한다. 재조회 중에는 기존 내용을 유지하되 갱신 중임을 알린다.
- 전송 중에는 해당 버튼의 중복 입력을 막는다. 실패 시 입력값을 유지하고 재시도 가능한 행동을 제공한다.
- 타임아웃은 처리 실패로 단정하지 않는다. 제출·승인·반려·취소 결과를 먼저 재조회하고, 이미 완료된 처리를 새로 만들지 않는다. STACK의 입력 데이터 계약·재시도 계획에 따라 같은 세션 ID를 유지하는 안으로 설계·검증한다. 실제 필드명과 응답 형식은 아직 비어 있는 API 문서에서 확정한다.
- 권한 오류는 보호된 정보를 숨기고 ‘이 기록을 볼 수 없어요’와 돌아가기 행동을 제공한다. 인증 만료는 로그인으로 안내한다.
- 앱이 백그라운드로 가면 촬영·추론을 중단하고 복귀 시 세션 상태를 안내한다. 불완전 기록을 정상 완료로 자동 제출하지 않는다. 재시작·종료의 구체 정책은 팀 결정 대상이다. (출처: STACK 추가 검증 항목)
- 오래 걸리는 처리는 상태 확인과 홈 이동을 제공한다. 근거 없는 완료율이나 자동 성공 표시는 하지 않는다.

| 화면 | 빈 화면·준비되지 않음 | 오류와 복구 | 로딩 |
| --- | --- | --- | --- |
| 계정·기본 설정 | ‘기본 정보를 설정해 주세요’와 필요한 입력 제공 | 입력 오류를 해당 필드 아래 표시. 로그인 실패 시 재시도 | 로그인·저장 중 버튼 비활성 |
| 홈 | ‘아직 운동 기록이 없어요’ + 운동 시작 | ‘기록을 불러오지 못했어요’ + 다시 불러오기 | 카드 자리 표시. 기존 기록 재조회 시 갱신 표시 |
| 운동 준비·튜토리얼 | 공략 대상이 없으면 ‘선택할 대상이 없어요’, 시작 제한 | 설정 조회 실패 시 다시 불러오기. 목표 입력 오류는 필드에 표시 | 기준·대상 로드 전 시작 비활성 |
| 카메라 운동 | 인체 미검출 시 ‘몸 전체가 화면에 보이도록 서 주세요’ | 권한 거부 시 설정 안내, 모델 실패 시 다시 준비. 프레임 이탈 시 미인정 사유 표시. 무작위 동작 확인 실패는 자동 승인 불가를 안내하고 이후 처리는 미정 | 카메라·모델 준비 중. 준비 전 운동 시작 제한 |
| 제출 상세·미리보기 | 없는 기록은 ‘기록을 찾을 수 없어요’ + 홈으로 | 계산 실패는 `SUBMITTED`, 지급 실패는 `APPROVED` 유지. 사용자에게 상태 확인 제공, 지급 재시도는 시스템 담당 | ‘기록 전송 중’, ‘보상 계산 중’, ‘보상 반영 중’을 실제 단계별 표시 |
| 확인 요청 미리보기 | 확인자 후보가 없으면 전송 비활성 및 안내. 후보 확보 방식은 미정 | 본인 선택·권한 오류는 전송 차단. 전송 결과 불명확 시 상태부터 확인 | 자료 조회·보내기 중 표시. 성공 전 `PREPARED` 유지 |
| 받은 확인 요청 | ‘받은 확인 요청이 없어요’ + 홈으로 | 처리된 요청이면 최신 상태 표시. 반려 코드·설명이 없으면 해당 입력에 오류 표시 | 요청 조회 중 표시. 승인·반려 처리 중 두 버튼 모두 비활성 |
| 리플레이·결과 | 지급 전이면 제출 상태로 안내. 상한 초과 0타는 전용 결과 카드 | 연출 로드 실패 시 수치 결과 카드로 이동. 결과 조회 실패는 재조회 | 리플레이 준비 중에도 결과 보기 제공. LLM 생성 때문에 보상 결과를 숨기지 않음 |

### LLM 결과 표시

- L1·L2는 ‘AI 참고 요약’, ‘AI 참고 설명’으로 표시한다. 확인자의 승인·반려 전에는 `PENDING_REVIEW`를 유지하고 확정 판정처럼 표현하지 않는다. (출처: 백로그 US-07·08)
- L3 전투 서사와 L4 교정 코멘트는 결과 카드의 확정 수치와 영역을 나눈다. 생성·재생성으로 보상이나 상태를 바꾸지 않는다. (출처: 백로그 US-02·05)
- LLM 실패 시 기본 문구를 사용하고 처리 진행을 막지 않는다. 기본 문구 예시 [제안]: 서사 ‘운동 기록이 전투에 반영됐어요’, 교정 ‘교정 안내를 불러오지 못했어요. 다음 운동 전 판정 기준을 확인해 주세요.’ 서사 예시는 지급 완료 화면에서만 사용한다. (출처: PRD 2·4절)
- 서사는 숫자·다른 스킬명·아이템명 검사, 교정 코멘트는 진단·처방 표현 검사를 거친 출력만 표시한다. 서사의 금지 항목과 2회 실패 시 대체 규칙은 정해져 있다. 교정 코멘트의 진단·처방 표현 판별 기준은 미정이다. (출처: PRD 2절, 백로그 US-05)

## 6. 접근성·구현 검토 기준 [제안]

아래는 구현 후 확인할 항목이며 아직 검증 완료한 목록이 아니다.

- [ ] 입력창에 항상 보이는 라벨과 접근성 이름을 제공한다. 플레이스홀더만으로 설명하지 않는다.
- [ ] 버튼·상태에 역할과 이름을 제공하고 TalkBack 탐색 순서를 화면 순서와 맞춘다.
- [ ] 외부 키보드로 주요 행동에 접근하고 실행할 수 있다.
- [ ] 터치 영역은 최소 `touchMin`을 확보하고 큰 글자에서도 내용·버튼이 잘리지 않는다.
- [ ] 본문 대비 4.5:1 이상, 큰 글자·컨트롤 경계 대비 3:1 이상을 실제 조합으로 확인한다.
- [ ] 인정·미인정·오류는 색과 문구로 함께 전달한다. 오류 발생 시 해당 입력을 찾을 수 있다.
- [ ] 운동 중 횟수 안내는 매 프레임 반복 낭독하지 않는다. 주요 상태 변화만 알린다.
- [ ] 리플레이에 스킵을 제공하고 모션 감소 설정에서는 결과 카드로 바로 이동할 수 있게 한다.

## 7. 문서 대조와 적용 범위

저장소 전체 파일 목록과 텍스트에서 디자인·화면·상태 관련 내용을 검색하고, PRD·백로그·사용자 흐름·스택·MVP 결정·도메인 규칙을 대조했다. 제안서 DOCX 2개는 본문 텍스트와 이미지 포함 여부를 확인했으며, 둘 다 내장 이미지가 없었다. 팀 지침·작업 로그·양식은 현재 구현 여부와 미정 사항을 구분하는 보조 자료로 사용했다.

| 대조 대상 | 확인한 내용 | 이 문서에 적용한 기준 |
| --- | --- | --- |
| PRD 9절 ↔ 앞선 DESIGN 초안 | PRD는 검정·라임인데 앞선 초안은 밝은 배경·보라색이었음 | PRD 색상·알약 버튼·실루엣·참고 대상을 반영 |

## 8. 미정 사항과 디자인 검토 항목

### 8-1. 원문에 남아 있는 미정 사항

이 표는 PRD·백로그의 미정 사항 중 화면 설계에 영향을 주는 항목이다. 이미 정해진 동작과 추가로 정해야 하는 정책을 구분한다. 담당·시점은 PRD의 ‘미정’ 표를 따르며, 원문에 없는 담당이나 날짜를 확정하지 않는다.

| 항목 | 이미 정해진 부분 / 남은 결정 | 담당·시점 (원문) | 출처 |
| --- | --- | --- | --- |
| 로그인 방식·앱 토큰 저장 | 로그인 본인 권한은 필요. 인증 방식·저장 방식은 미정 | 팀, 뼈대 세우기 전 | PRD 미정, STACK 예상 어려움과 대응 |
| 무작위 동작 확인 실패 | 자동 승인 불가. 세션 재시작 / 제출하되 자동 승인 제외 중 처리 방식 미정 | 팀 회의, US-01 구현 시작 전. 정리 담당 미정 | PRD 미정, 백로그 US-01·03 |
| 촬영 각도 | 준비 화면에서 안내해야 함. 실제 권장 각도는 테스트 후 결정 | 팀, 첫 데모 전 카메라 각도 테스트 후 | PRD 미정, 백로그 US-01 |
| 확신도 기준·계산 | 현재 요구사항은 90% 기준. 최종 기준값과 계산 방법은 검증·결정 필요 | 기준: 팀, 첫 데모 전 모델 테스트 후. 계산: 강준석·김지은, US-03 구현 시작 전 | PRD 미정, 백로그 US-03 |
| 공략 대상 | 대상 선택·피해 반영은 포함. 던전 적 / 주간 보스 중 데모 대상 미정 | 팀 회의, US-02·US-04 구현 시작 전 (첫 데모 전) | PRD 미정, 백로그 US-04 |
| LLM 기본 문구·생성 대상 | 장애 시 기본 문구로 진행. 최종 문구와 자동 승인 건의 L1·L2 생성 여부 미정 | 팀 회의, US-02 구현 시작 전 | PRD 미정, 백로그 US-02 |
| 교정 표현 필터 | 진단·처방 표현을 걸러야 함. 판별 기준 미정 | 팀 회의 | PRD 미정, 백로그 US-05 |
| 취소 가능한 시점 | 승인 전 세 상태에서 취소 가능. 빠른 자동 승인 경로에서 사용자에게 제공할 조작 시간 미정 | 팀 회의, US-06 구현 시작 전 | PRD 미정, 백로그 US-06 |
| 지인 선택·무응답 | 지인·길드장 1명에게 요청. 지인 정의와 미전송·무응답 처리 미정 | 팀 회의, US-07 구현 시작 전 | PRD 미정, 백로그 US-07 |

### 8-2. 이 문서에서 제안한 디자인·구현 세부사항

아래는 기존 요구사항 전체가 미정이라는 뜻이 아니다. 현재 문서에 제시한 안과 구현 전에 확인할 세부사항이다. 검토 담당·시점은 별도로 합의되지 않았다.
