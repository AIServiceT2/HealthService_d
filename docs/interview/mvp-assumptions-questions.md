# 5. MVP 가설, 기능 목록, 가정·위험, 클라이언트 질문지, 미팅 준비

> 목표: 우리가 만들 것과 모르는 것을 목록으로 만들고, 모르는 것을 클라이언트가 답할 수 있는 질문으로 바꾼다.

## 5-1. MVP 가설

> 클라이언트 미팅 전 우리의 추측입니다. 미팅 뒤 바뀔 수 있습니다. 제안서 Ⅰ-3 제안 범위, Ⅳ-10 목표 흐름의 바탕이 됩니다.

| 구분 | 내용 |
| --- | --- |
| 핵심 사용자 흐름 1개 (첫 데모에서 보여 줄 것) | 플레이어가 스쿼트 30회를 하고 앱 캡처와 함께 제출(`SUBMITTED`) → 규칙 엔진이 보상·타격 수를 계산해 스냅샷을 고정하고 미리보기 "충격파 스톰프 ×30"을 보여 줌(`PREPARED`) → 다른 길드 검토자에게 배정(`PENDING_REVIEW`) → 검토자가 증빙의 운동 종류·운동량을 확인하고 승인(`APPROVED`) → 경험치·아이템·던전 공략·보스 체력이 트랜잭션으로 **정확히 한 번** 반영(`REWARDED`) → 홈의 '전투 결과 도착' 카드에서 캐릭터가 스쿼트 충격파로 30번 공격하는 리플레이(30 COMBO)와 결과 카드를 봄. (기획서 v3 17장 M1 완료 기준) |
| 이 흐름에서 LLM이 쓰이는 곳 | ① `PREPARED`에서 기록 요약(L1)과 이상치 설명(L2)을 만들어 검토 화면 상단에 보여 줌 → 검토자가 증빙과 비교해 판단. ② 같은 시점에 전투 서사(L3)를 만들어 리플레이 뒤 결과 카드와 함께 보여 줌 → 규칙 검사로 숫자·다른 스킬명을 거름. 셋 다 실패해도 기본 문구로 흐름은 그대로 진행 ([3-4](../domain/03-rules-states-llm.md#3-4-llm이-들어갈-자리)) |
| 당장 제외할 것과 이유 | **첫 데모(M1)에서 제외:** 나머지 3종 스킬·약점 배율(M2), 반려·재제출·취소·신고·회수 예외 경로(M2), 숙련도 이펙트·보상 상자 연출·운동 중 모드(M3) → 정상 경로 하나를 먼저 끝까지 돌리기 위해. **MVP 전체에서 제외:** 확장 운동 4종·서킷 제출, 스킬 연계 콤보, 카메라 자세 인식, GPS·웨어러블 직접 연동, 거래·강화·제작, 직업·길드 채팅, 여러 지역·막타 보너스, 자유 대화형 NPC, 고도화된 도용 탐지 → 5명·8주 안에서 가장 큰 작업인 스킬 애니메이션에 시간을 쓰기 위해 (기획서 v3 17장·18장) |

## 5-2. 주요 기능 목록

> 5~8개. '필수'는 첫 데모에 꼭 있어야 하는 기능, '선택'은 시간이 되면 만드는 기능입니다. 제안서 Ⅳ-11의 바탕이 됩니다.

| ID | 기능명 | 설명 | 사용자 | 우선순위 (필수/선택) | 관련 상태 전이 / LLM |
| --- | --- | --- | --- | --- | --- |
| F-01 | 회원·캐릭터·길드 | 가입, 나를 닮은 아바타(헤어·피부색·의상) 만들기, 길드 가입. 운동량에 따른 체형 변화는 넣지 않음 | 플레이어 | 필수 | 상태 전이 없음 (검토자 배정에 길드 정보 사용) |
| F-02 | 운동 제출·재제출·취소 | 카탈로그에서 운동 선택(부위·스킬 자동 표시), 시각·운동량·증빙 1~3장·공략 층 입력. 48시간 기한·시간대 중복·일일 상한 검사. 첫 데모는 스쿼트 1종, M2에서 1차 4종 | 플레이어 | 필수 | → `SUBMITTED`, `REJECTED → SUBMITTED`, `→ CANCELED` |
| F-03 | 보상 계산·미리보기 | 규칙 엔진이 경험치·총 피해량·타격 수·드랍·상한을 계산하고 스냅샷 고정. 미리보기 "충격파 스톰프 ×30"과 상자 개수 표시 | 시스템 (플레이어가 결과 확인) | 필수 | `SUBMITTED → PREPARED`, LLM L1·L2·L3 생성 |
| F-04 | 타 길드 검토 | 무작위 배정, 12시간 재배정·24시간 운영자 이관. 증빙·입력값·AI 요약·이상치를 보고 승인 또는 사유 코드와 함께 반려 | 타 길드 검토자, 운영자 | 필수 | `PREPARED → PENDING_REVIEW → APPROVED / REJECTED`, LLM L1·L2 표시 |
| F-05 | 멱등 지급과 던전·레이드 반영 | 경험치·아이템·던전 공략·보스 피해를 트랜잭션으로 정확히 한 번 지급, 24시간 보호 기간(아이템 `LOCKED`, 숙련도 확정 대기) | 시스템 | 필수 | `APPROVED → REWARDED`, 보스 `ACTIVE → DEFEATED` |
| F-06 | 전투 리플레이·결과 카드 | 제출한 운동 동작으로 실제 횟수만큼 공격하는 리플레이(최대 30초, 스킵 가능)와 수치가 담긴 결과 카드 | 플레이어 | 필수 | `REWARDED` 이후 표시, LLM L3 서사 |
| F-07 | 신고·회수 | 보호 기간 안에 신고 접수, 다른 검토자 검토 후 운영자 확정, 지급 내역을 반대로 적용해 회수. 하루 3건·기각 3회 시 7일 정지 | 신고자, 사진 원작자, 운영자 | 선택 (첫 데모 이후, M2) | `REWARDED → REVOKED`, 신고 `OPEN → UNDER_REVIEW → UPHELD / DISMISSED` |
| F-08 | 운동 중 모드 | 세트마다 탭하면 캐릭터가 한 번 공격하는 미니 연출. 기록은 제출 폼 자동 채움용(증빙 아님) | 플레이어 | 선택 (M3, 여유 시) | 상태 전이 없음 (F-02 입력 보조) |

## 5-3. 가정 목록

> 1~4단계에서 `[가정]`·`[추정]` 태그를 붙인 것을 모읍니다. 틀렸을 때 피해가 큰 것부터 적습니다. 제안서 Ⅶ-16의 바탕이 됩니다.

| 번호 | 가정 | 나온 곳 | 틀리면 바뀌는 것 | 중요도 (상/중/하) |
| --- | --- | --- | --- | --- |
| H1 | 실제로 한 운동이 스킬·콤보가 되는 전투 리플레이가 사용자를 몇 주 이상 계속 운동하게 만든다 | 기획서 v3 1장·10장, [4-Kangjunseok09-1](../domain/cards/4-Kangjunseok09-1.md) (게이미피케이션 효과는 있지만 개입이 끝나면 줄어듦 → 우리 서비스의 장기 효과는 `[가정]`) | 서비스의 핵심 가치가 흔들림. 리플레이보다 길드 협동·목표 설정 같은 다른 동기 장치에 무게를 옮겨야 함 | 상 |
| H2 | 다른 길드 사용자가 배지 보상만으로도 남의 제출건을 제때, 성실하게 검토한다 | 2-1 검토자 불편, 3-1 R4, 3-3 재배정 규칙 | 검토 대기가 길어져 흥미가 식고, 운영자 검토함이 넘침. 표본 검토·운영자 중심 검토로 바꾸거나 검토 보상을 다시 설계해야 함 | 상 |
| H3 | 사진·앱 캡처 증빙만으로 운동량을 판단할 수 있다. 특히 근력 운동(스쿼트·푸시업)의 횟수를 사진으로 확인할 수 있다 | 2-1 검토자 불편, 기획서 v3 6장 증빙 신뢰도 계수 (사진만 0.5) | 근력 운동 보상을 믿기 어려워 검토 기준이 무너짐. 운동 중 모드·영상 증빙·자세 인식 같은 다른 증빙 방식을 앞당겨야 함 | 상 |
| H4 | 1차 4종 스킬의 픽셀 애니메이션(준비 → 동작 → 타격 → 피니시)을 8주 안에 만들 수 있다 | 기획서 v3 18장 아트 범위 | 리플레이 품질이나 스킬 수를 줄여야 하고, M2·M3 범위가 바뀜 | 중 |
| H5 | 증빙 원본 대신 서버에서 뽑은 글자(OCR)만 보내도 LLM이 "선택한 운동은 스쿼트지만 캡처는 러닝 앱 화면" 같은 이상치를 설명할 수 있다 | 3-4 결정 필요, 2-3 개인정보 | 가린 이미지를 보내야 해서 개인정보 처리 방식과 동의 절차가 바뀜. 또는 L2를 규칙 검사 결과만으로 줄여야 함 | 중 |

## 5-4. 위험 요소

> 2~3개. 예: LLM이 틀린 답을 낸다, 개인정보가 LLM에 들어간다, 기능이 늘어나 8주 안에 못 끝낸다. 제안서 Ⅶ-17의 바탕이 됩니다.

| 위험 | 일어나면 생기는 일 | 대응 |
| --- | --- | --- |
| 스킬 애니메이션·연출 작업이 커서 8주 안에 끝내지 못한다 | 핵심 가치인 전투 리플레이가 시연 때 완성되지 않음. 다른 기능 일정까지 밀림 | M1은 스쿼트 1종만 완성하고 나머지는 M2로 미룸. 숙련도별 이펙트 단계를 줄이고 공용 이펙트를 재사용. 3주차에 아트 진행 상황을 보고 스킬 수를 다시 정함 (H4) |
| 증빙 속 개인정보(경로 지도의 집 위치, 얼굴, 심박)가 LLM이나 다른 길드 검토자에게 노출된다 | 위치·건강 정보 유출, 사용자 신뢰 하락 | LLM에는 구조화된 값과 OCR 글자만 보내고 원본 이미지는 보내지 않음(H5). 업로드 때 시작·끝 지점 가리기 안내. 원본은 신청자·배정된 검토자·운영자만 열람 |
| LLM이 틀린 요약·이상치·서사를 낸다 | 오탐으로 정상 건이 반려되거나, 서사와 결과 카드의 숫자가 달라 혼란 | LLM 출력은 `ai_*` 필드에만 저장하고 자동 반려에 쓰지 않음. 서사는 숫자·다른 스킬명·아이템명이 있으면 거부하고 2회 실패 시 기본 문구. LLM 장애에도 상태 진행은 그대로 |

## 5-5. 클라이언트 질문지

> 카테고리마다 1개 이상, 총 8~10개. 미팅 질문 시간은 팀당 약 12분이므로 우선순위 1~5번은 반드시 묻는 질문입니다. **1~3번은 제안서 Ⅶ-18에 넣어 미리 보냅니다.** 질문을 고칠 때 팀원끼리 서로 읽어 보고 예/아니오로 끝나거나 답을 유도하는 질문을 고칩니다.
>
> 좋은 질문의 조건: ① 예/아니오로 끝나지 않는다 ② 구체적인 사례를 들어 묻는다 ③ 우리 해결책을 정답으로 유도하지 않는다 ④ 답을 들으면 무엇을 결정할지 알고 있다.

| 우선순위 | 카테고리 | 질문 | 관련 가정 | 이 답으로 결정할 것 |
| --- | --- | --- | --- | --- |
| 1 | 목적·성공 기준 | | | |
| 2 | 사용자·권한 | | | |
| 3 | 규칙 | | | |
| 4 | 상태 전이·예외 | | | |
| 5 | 우선순위·범위 | | | |
| 6 | LLM 결과의 확인과 책임 | | | |
| 7 | 데이터·외부 연동·개인정보 | | | |
| 8 | 완료 기준 (어떻게 확인하면 되나) | | | |
| 9 | | | | |
| 10 | | | | |

> 질문지를 Claude에게 보여 주고 '빠진 관점'을 물어본 결과는 [ai-check-log.md](../domain/ai-check-log.md#질문지-검토-5단계)에 적습니다.

## 5-6. 미팅 역할 분담

> 실제 클라이언트 미팅에서 다섯 명이 하나씩 맡습니다. [팀 역할](../team/roles.md)과 따로 정해도 됩니다.

| 역할 | 하는 일 | 담당 |
| --- | --- | --- |
| 진행자 | 질문 순서·시간 관리, 꼬리 질문 | |
| 기록자 | 답변을 말 그대로 기록 | |
| 꼬리 질문자 | "예를 들면요?", "그 경우 누가요?"로 파고들기 | |
| 시간·가정 체커 | 가정 H1~H5 중 확인된 것을 지우기 | |
| 요약·확인자 | 끝나기 1분 전, 들은 답을 3문장으로 되읽어 클라이언트에게 맞는지 확인 | |

## 5-7. 미팅 전에 다시 볼 것

> 제안서를 보낸 뒤 미팅까지 팀이 함께 확인합니다.

| 확인할 것 | 메모 |
| --- | --- |
