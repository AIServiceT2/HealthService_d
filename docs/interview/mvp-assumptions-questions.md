# 5. MVP 가설, 기능 목록, 가정·위험, 클라이언트 질문지, 미팅 준비

> 목표: 우리가 만들 것과 모르는 것을 목록으로 만들고, 모르는 것을 클라이언트가 답할 수 있는 질문으로 바꾼다.

## 5-1. MVP 가설

> 클라이언트 미팅 전 우리의 추측입니다. 미팅 뒤 바뀔 수 있습니다. 제안서 Ⅰ-3 제안 범위, Ⅳ-10 목표 흐름의 바탕이 됩니다.

| 구분 | 내용 |
| --- | --- |
| 핵심 사용자 흐름 1개 (첫 데모에서 보여 줄 것) | 플레이어가 카메라 앞에서 스쿼트 30회를 함 → 기기 안에서 관절 위치로 인정 렙 30회가 인식되고 세션 종료 시 자동 제출(`SUBMITTED`, 영상은 기기 밖으로 나가지 않음) → 규칙 엔진이 보상·타격 수를 계산해 스냅샷을 고정하고 미리보기 "충격파 스톰프 ×30"을 보여 줌(`PREPARED`) → 다른 길드 검토자에게 배정(`PENDING_REVIEW`) → 검토자가 스켈레톤 리플레이와 인정·미인정 렙을 보고 사람이 실제로 한 운동인지 확인해 승인(`APPROVED`) → 경험치·아이템·능력치 경험치·던전 공략·보스 체력이 트랜잭션으로 **정확히 한 번** 반영(`REWARDED`) → 홈의 '전투 결과 도착' 카드에서 캐릭터가 스쿼트 충격파로 30번 공격하는 리플레이(30 COMBO)와 결과 카드를 봄. (기획서 v4 기준, [03 3-2](../domain/03-rules-states-llm.md#3-2-핵심-대상과-상태-전이)) |
| 이 흐름에서 LLM이 쓰이는 곳 | ① `PREPARED`에서 기록 요약(L1)과 이상치 설명(L2)을 만들어 검토 화면 상단에 보여 줌 → 검토자가 스켈레톤 리플레이·연동 기록과 비교해 판단. ② 같은 시점에 전투 서사(L3)를 만들어 리플레이 뒤 결과 카드와 함께 보여 줌 → 규칙 검사로 숫자·다른 스킬명을 거름. 셋 다 실패해도 기본 문구로 흐름은 그대로 진행 ([3-4](../domain/03-rules-states-llm.md#3-4-llm이-들어갈-자리)) |
| 당장 제외할 것과 이유 | **첫 데모(M1)에서 제외:** 나머지 3종 스킬·약점 배율(M2), 반려·재제출·취소·신고·회수 예외 경로(M2), 숙련도 이펙트·보상 상자 연출·운동 중 모드(M3) → 정상 경로 하나를 먼저 끝까지 돌리기 위해. **MVP 전체에서 제외:** 확장 운동 4종, 스킬 연계 콤보, GPS 경로·심박 수집(건강 앱에서는 걸음 수·러닝 세션만), 웨어러블 직접 연동(건강 앱 경유만), 거래·강화·제작, 직업·길드 채팅, 여러 지역·막타 보너스, 자유 대화형 NPC, 고도화된 도용 탐지 → 5명·8주 안에서 가장 큰 작업인 카메라 인식과 스킬 애니메이션에 시간을 쓰고, 동의 범위를 넘는 건강·위치 정보를 모으지 않기 위해 (기획서 v4, 03 3-1 R17) |

## 5-4. 위험 요소

> 2~3개. 예: LLM이 틀린 답을 낸다, 개인정보가 LLM에 들어간다, 기능이 늘어나 8주 안에 못 끝낸다. 제안서 Ⅶ-17의 바탕이 됩니다.

| 위험 | 일어나면 생기는 일 | 대응 |
| --- | --- | --- |
| 스킬 애니메이션·연출 작업이 커서 8주 안에 끝내지 못한다 | 핵심 가치인 전투 리플레이가 시연 때 완성되지 않음. 다른 기능 일정까지 밀림 | M1은 스쿼트 1종만 완성하고 나머지는 M2로 미룸. 숙련도별 이펙트 단계를 줄이고 공용 이펙트를 재사용. 3주차에 아트·카메라 인식 진행 상황을 보고 스킬 수를 다시 정함 (H4) |
| 신체 정보(카메라 영상, 관절 좌표)나 건강·생활 패턴 정보가 LLM이나 다른 길드 검토자에게 노출된다 | 신체·건강 정보 유출, 민감정보 처리 문제, 사용자 신뢰 하락 | 영상은 저장하거나 기기 밖으로 보내지 않고, 서버에는 얼굴 랜드마크를 뺀 관절 좌표와 렙 타임스탬프만 보냄(R11). 검토자는 실제 영상·얼굴 대신 스켈레톤 리플레이만 봄. LLM에는 구조화된 값과 숫자 통계만 보냄(H5). 건강 앱에서는 걸음 수·러닝 세션만 가져오고 GPS 경로·심박은 가져오지 않음(R17) |
| 카메라 인정 기준(관절 각도)을 잘못 잡는다 | 너무 엄격하면 정상 렙이 억울하게 미인정되고, 너무 느슨하면 반쪽 동작으로 횟수를 부풀림 (2-1 운영자) | 운영자가 카탈로그를 버전으로 관리하고 제출건은 `PREPARED` 스냅샷의 버전으로 계산(R5). 각도 문제로 미인정되면 촬영 위치 안내 후 새 세션(R12). 첫 데모 전 팀원 시연으로 기준을 맞춤 (H3) |
| LLM이 틀린 요약·이상치·서사를 낸다 | 오탐으로 정상 건이 반려되거나, 서사와 결과 카드의 숫자가 달라 혼란 | LLM 출력은 `ai_*` 필드에만 저장하고 자동 반려에 쓰지 않음. 서사는 숫자·다른 스킬명·아이템명이 있으면 거부하고 2회 실패 시 기본 문구. LLM 장애에도 상태 진행은 그대로 |

## 5-5. 클라이언트 질문지

> 카테고리마다 1개 이상, 총 8~10개. 미팅 질문 시간은 팀당 약 12분이므로 우선순위 1~5번은 반드시 묻는 질문입니다. **1~3번은 제안서 Ⅶ-18에 넣어 미리 보냅니다.** 질문을 고칠 때 팀원끼리 서로 읽어 보고 예/아니오로 끝나거나 답을 유도하는 질문을 고칩니다.
>
> 좋은 질문의 조건: ① 예/아니오로 끝나지 않는다 ② 구체적인 사례를 들어 묻는다 ③ 우리 해결책을 정답으로 유도하지 않는다 ④ 답을 들으면 무엇을 결정할지 알고 있다.

| 우선순위 | 카테고리 | 질문 | 관련 가정 | 이 답으로 결정할 것 |
