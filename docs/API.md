# API 약속 (화면과 서버가 주고받는 것)

> **저장 위치:** `docs/API.md`

> **사용 방법**
> 1. 오늘은 **오늘 만든 기능 하나의 항목만** 씁니다. 전체 API는 다음 차시 이후에 채웁니다. 개발자1과 개발자2가 **구현하기 전에 같이 읽고 약속**하는 문서이기도 합니다.
> 2. 항목의 **입력·출력·실패 응답**은 `backlog.md`의 **인수 조건**과 `first-feature.md` 2절에서 가져옵니다. 인수 조건에 없는 응답을 새로 만들지 않습니다.
> 3. 필드 이름·상태값은 `DATA-MODEL.md`와 **똑같이** 씁니다.
> 4. 이 문서는 **공유 파일**입니다. PM만 고치고, 바꿀 일이 있으면 PR 댓글로 요청합니다. 개발자1과 개발자2가 합의한 약속을 PM이 옮겨 적습니다.
> 5. 모르는 것은 `미정`으로 씁니다. 임의로 정하지 않습니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

## 항목 1: 보상·타격 수 미리보기 (기능 ID: F-03 / 스토리: US-02)

> 오늘 범위는 LLM 없이 `SUBMITTED → PREPARED` 계산과 미리보기 조회까지다 (출처: first-feature.md 1절).

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | ① 보상 계산: 시스템이 `SUBMITTED` 제출건을 계산 — 경로·방식 미정 (사용자 버튼이 아니라 시스템이 실행하는지, 오늘은 수동 호출로 대신하는지 합의 필요) ② 미리보기 조회: 화면이 제출건 1건을 조회 — 경로·방식 미정 |
| 입력 | ① 제출건 `id` ② 제출건 `id` (출처: DATA-MODEL.md WorkoutSubmission) |
| 출력 (성공) | 제출건의 `status`=`PREPARED`, `counted_reps`, `snapshot`의 타격 수 (인정 렙 30회 스쿼트 → 30). 스냅샷 안 키 이름은 미정 (출처: first-feature.md 2절 #1, DATA-MODEL.md '아직 정하지 못한 것' 영문 필드 이름) |
| 실패 응답 | 보상 계산 실패 시 `status`는 `SUBMITTED`에 남고, 재시도해서 성공했을 때만 `PREPARED`가 된다 (출처: first-feature.md 2절 #3). 오류 코드·본문 형식은 미정 |
| 권한 (누가 못 하나) | 오늘은 만들지 않음. 다른 사용자의 미리보기 요청 거부는 로그인 방식이 정해진 뒤 (출처: first-feature.md 2절 #5) |
| 바뀌는 상태 | `SUBMITTED` → `PREPARED` (①에서만. ② 조회는 상태를 바꾸지 않음) |
| 관련 인수 조건 | `first-feature.md` 2절 #1, #3 |
| 화면이 쓰는 곳 | `DESIGN.md` '제출 상세·보상 미리보기' |

### 입력·출력 예시
> 필드 이름은 DATA-MODEL.md 그대로. 경로와 스냅샷 안 키 이름은 미정이라 비워 둠. DATA-MODEL.md 시드에는 `SUBMITTED` 건이 없어(시드 2번 `s1`은 이미 `PREPARED`) 계산 시험용 시드는 개발자1과 정해야 함.
```
요청: (경로 미정) 제출건 id = (SUBMITTED 시드, 미정)
응답(성공): { "id": ..., "status": "PREPARED", "counted_reps": 30, "snapshot": { (타격 수 키 미정): 30 } }
응답(실패): 계산 실패 → 제출건 "status": "SUBMITTED" 유지 (오류 본문 형식 미정)
```
